# RetroSVR Swift standards (project)

Project-specific rules and facts for the macOS port in `macos/`. These override
`~/.claude/swift-standards.md` where they disagree. The rest of the repo is the
original C#/.NET Windows screensaver and is out of scope for Swift review.

Last verified: 2026-11-19

## Conventions observed

- Headers follow the global format exactly. `Package.swift` uses a two-line prose comment.
- `RetroSVRCore` must not import AppKit, AVFoundation or ScreenSaver; platform behaviour
  reaches it through `DissolverEffect.Hooks` closures.
- The core is single-threaded and main-thread-only by contract, so its types are plain
  non-`Sendable` classes rather than `@MainActor`. The Saver wraps hook bodies in
  `MainActor.assumeIsolated`. Don't flag the lack of actor annotations in the core.
- Comments that explain a deviation from the Windows version are intentional; the list of
  deviations lives in `macos/README.md` under "Differences from the Windows version".
- Opt-in snapshot tests are gated on `RETROSVR_SNAPSHOT_DIR`.
- Logging uses `os.Logger` with subsystem `SettingsStore.moduleName`.

## ScreenSaver host facts

- One `ScreenSaverView` per display plus a preview thumbnail (`isPreview`).
- Since macOS 14 the host doesn't reliably call `stopAnimation()`; the view listens for
  the `com.apple.screensaver.willstop` distributed notification instead. Community reports
  also say views aren't deallocated after dismissal, so per-view memory accumulates.
- Apple's docs allow `animateOneFrame()` to be called after `stopAnimation()`.
- Settings live in `ScreenSaverDefaults` under module name `com.todddube.RetroSVR`.

## Commands

- Test: `cd macos/RetroSVRCore && swift test`
- Build: `xcodebuild -project RetroSVR.xcodeproj -scheme RetroSVR -configuration Release -derivedDataPath build/DerivedData build` (from `macos/`); same for `-scheme RetroSVRApp`.
- Avoid in review: `scripts/install.sh` (installs into `~/Library/Screen Savers` and kills the host).
